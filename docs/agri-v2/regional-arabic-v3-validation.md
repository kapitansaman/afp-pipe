## Fixed execution boundary

- One create-only remote reservation; exact manual base-branch identity.
- At most TWO text transports: one tiny 256-token/45s health check and ONE
  Arabic v3 review (14000 tokens/180s). No English, Russian or Tajik transport.
- Exactly one owned central credential slot, AGNES_API_KEY81. No rotation,
  fallback/borrowing, image transport or production capacity health renewal.
- At most THREE freshly fetched exact fact-linked original source URLs,
  shared source helper only. No public search, query planner, discovered links,
  stale text re-dating or second fetch round. Existing institutional HTTPS,
  public-DNS, <=5 safe redirect hops, document hashes, link version and 6-hour
  TTL gates remain active. All three originals must be valid before the review.
- No site calls, edits to articles/translations, attempts reset, publication,
  production approvals, schedule activation or staged promotion.

The health proof is isolated, actual, bound to this new request/connection and
valid for only this run's next review (<1 hour). A v2 health proof or expired
full-capacity audit cannot substitute. Native schema, full fresh documents,
v3 context policy, numeric candidates, quote catalogs and actual role-enriched
payload are rebuilt and hash-bound. The unchanged 200000-character transport
ceiling applies; no evidence/prompt clipping or country/gap filling is allowed.
The raw answer must independently meet every existing server validator. A
properly bound negative is retained as a diagnostic, never auto-corrected into
a positive. Even a positive produces no production approved.json.

Every transport is reserved before send, one attempt, no retry. Existing
routing counters, disabled slots and shared provider holds survive. An existing
own report, unknown output or conflicting durable reservation blocks replay.
The final integrity report checks all other original data/artifacts bytewise.

## What this does not authorize

This diagnostic cannot establish production capacity, four-language acceptance,
visual QA, fresh authenticated/public site health or staged 1 → 3 → 20 approval.
Those remain separate gates. Publication and recurring schedules remain OFF.
No additional paid testing is implicitly authorized by a negative or a failure.
