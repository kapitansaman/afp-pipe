# درخواست یک‌باره رفع مانع و اجرای پایلوت

این مسیر برای دستور مالک جهت رفع موانع و اجرای قدم بعد افزوده شد؛ جایگزین جعل رویداد workflow_dispatch یا روشن‌کردن زمان‌بندی عمومی نیست.

- فقط push روی main و مسیر `.github/afp-operations/request.json` در گردش‌کار مشخص مخزن مقصد مجاز است.
- درخواست در SHA همان push خوانده می‌شود؛ نسخه کد checkoutشده باید دقیقاً با commit تعیین‌شده درخواست تطبیق داشته باشد.
- شناسه ثابت `ops-97-readiness-pilot-v1` رزرو create-only دارد. اجرای مجدد یا تغییر فایل درخواست اجازه مصرف دوباره همین عملیات را نمی‌دهد.
- بررسی احراز هویت و OPTIONS وردپرس فقط‌خواندنی است؛ مقادیر سکرت یا پاسخ خام ارائه‌دهنده در گزارش ذخیره نمی‌شود.
- حداکثر ۹۷ آزمون متن با دو درخواست همزمان؛ فقط یک آزمون مستقل تصویر، بدون تلاش کلید دیگر بعد از خطا. خطای مشترک/نامطمئن توقف ایجاد می‌کند.
- شاهد تصویر نام `actual_successful_parallel_capability_probe` دارد؛ اثبات موفقیت تولید تصویر است، نه تأیید بصری مقاله و نه تمدید تاریخ آزمون متن.
- قبل از شروع پایلوت، شواهد در شاخه پیشرفت ثبت می‌شود. سپس فقط خانواده مالک موضوع پایلوت ادامه می‌یابد؛ بودجه‌ها، بازبینی منبع، همپوشانی، کنترل مقاله/تصویر و انتشار عمومی همچنان الزامی‌اند.
- حداکثر یک خانواده پایلوت مجاز است؛ ممکن است یک پست منبع و ترجمه‌های مجاز آن داشته باشد. دروازه research-only سایر ۱۹ خانواده و زمان‌بندی خودکار باز نمی‌شود.
- نتیجه ناموفق مرحله آماده‌سازی مانع اجرای پایلوت می‌شود. گزارش sanitized به‌عنوان artifact نیز حفظ می‌شود.

آزمون محلی در زمان ساخت این مسیر: ۵۲۷ تست پاس. این سند موفقیت اجرای زنده را ادعا نمی‌کند؛ نتیجه واقعی در `artifacts/agri-v2/parallel/operations/ops-97-readiness-pilot-v1/` و GitHub Actions ثبت می‌شود.
