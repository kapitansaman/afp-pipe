# Model-led repair of insufficient source coverage

The source-discovery model diagnoses the missing species/product/method evidence and proposes up to four HTTPS institutional document or search/index leads. This is NOT a claim that the model has browsed the web, nor a new custom agent. It uses the existing isolated family's text client and owned keys.

## Actual path

1. An original extraction failed for explicit insufficient scope or too few valid facts, with an original attempt still available; or a bounded source fetch demonstrated an initial catalog/coverage gap (not a temporary network error).
2. `research_discover`: at most one planning call and one original stage attempt. Persist exact topic/input hashes, diagnosis, query plans and UNVERIFIED URL leads. Invalid/foreign/private URLs fail closed. Query strings are not represented as executed search results.
3. `research_refetch`: at most one API-free fetch stage, up to twelve source reads using the existing institutional HTTPS/public-DNS/per-redirect/size/PDF safeguards and observed-link navigation. Search/index pages are discovery-only and excluded from agronomic evidence. A model may propose a real institutional search URL, but there is no generic search-engine API integration or guarantee that it works.
4. Replace the evidence pack only if structurally verified new source content was fetched. Preserve old sources, raw candidate, diagnostic feedback and discovery report in a write-ahead archive. Old evidence IDs are never reused against the new pack.
5. Run the ORIGINAL extraction with its remaining attempts, then all original overlap, independent scientific, quality and publication gates. A fetched page is not scientific acceptance.

## Ownership and failure handling

- No model/editor rewrites rejected article text to manufacture support.
- No credential or provider is added. Existing family partitions, global request limits, account holds and uncertainty fences still apply.
- Unknown planning/refetch reservations cannot be bypassed even if a crash removed the old raw candidate. A partially changed evidence pack requires explicit reconciliation.
- Empty or failed discovery preserves old inputs. Initial coverage failures can enter the existing research backlog after this finite discovery opportunity. Retries never form an unbounded URL crawl/model loop.
- Existing exhausted or deferred topics are NOT automatically re-entered and their budgets are NOT reset. This implementation is for active/new work with remaining authorization. Re-entry needs separate explicit admission.
- Rejected independent scientific/overlap verdicts, accepted briefs/articles, publication receipts and explicit holds are protected from source-repair overwrite.
- Scoped research-only rollout and per-family actual image-capability requirements are unchanged. This is not proof of full production readiness.

## Tests and acceptance

Regression tests cover missing catalogs, actual observed-link navigation, inaccessible/unsafe/model-invented leads, unchanged counters, source archives, old-ID invalidation, unknown/partial writes, independent-review protection and the real worker sequence planner -> fetch -> original extraction. Live model/source discovery must be reported separately from mocked regression coverage.
